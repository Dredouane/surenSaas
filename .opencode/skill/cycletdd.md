\---\nname: cycletdd\ndescription: Use ONLY when the user wants to execute code using a Test-Driven Development (TDD) cycle, including writing tests, running them, and then implementing the code.\n---\n\n# Cycle TDD Skill\n\nThis skill automates the Test-Driven Development (TDD) cycle:\n\n1.  **Write Tests:** Generate unit tests based on the user's requirements or existing code.\n2.  **Run Tests:** Execute the tests using the project's testing framework.\n3.  **Implement Code:** Write or modify the application code to make the tests pass.\n4.  **Re-run Tests:** Verify that the implemented code passes all tests.\n\n## Usage\n\nWhen a user wants to implement a feature using TDD:\n\n1.  **Analyze Request:** Understand the feature requirements and identify necessary tests.\n2.  **Generate Tests:** Use `cycletdd` to create the initial unit tests.\n3.  **Run Tests:** Execute the generated tests. They should fail initially.\n4.  **Implement Code:** Write the minimal code required to pass the tests.\n5.  **Verify:** Run tests again to confirm the code works as expected.\n\n**Example Workflow:**\n\nUser: \"Implement a function to calculate the factorial of a number using TDD.\"\n\nAgent: Use `cycletdd` skill. Provide the requirements.\n\nSkill Output:\n- Generated test file (`test_factorial.py`).\n- Command to run tests (`pytest test_factorial.py`).\n- Placeholder for factorial function implementation.\n- Instructions to run tests again after implementation.\n
