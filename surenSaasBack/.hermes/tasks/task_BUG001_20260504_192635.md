# Task: BUG-001 — Colonne `status` → `statut` (pointages) + parsing des dates

## Objective
Le handler `handle_validate_pointage` et `handle_toggle_presence` dans le bot pointages Telegram utilisent la colonne `statut` (correct depuis l'avant-dernier commit).
Mais l'écosystème autour utilise encore `status`.

Corriger TOUS les usages de `status` en `statut` dans les fichiers listés ci-dessous, SAUF les imports/signatures/clés standard Python qui n'ont rien à voir avec la DB.

## Context

### Error / Symptom
Le test `test_validate_pointage_uses_statut_column` échoue avec :
```
assert "status" not in update_kwargs
```
Car le handler `handle_validate_pointage` met à jour la DB pointages avec la clé `status` au lieu de `statut`.

Les tests `test_pointage_date_parsing` échouent car les dates sont parsées via `date.fromisoformat()` qui ne gère pas les formats européens "DD/MM/YYYY".

### Relevant Files

**`surenSaasBack/app/api/bot_construction_pointages.py:23-27`**
```python
def _format_date_display(date_str: str) -> str:
    \"\"\"Formate une date ISO pour l'affichage.\"\"\"
    d = date.fromisoformat(date_str)
    return d.strftime(\"%d/%m/%Y\")
```
BUG: `date.fromisoformat()` lance ValueError si l'entrée est au format "24/04/2026" (européen).
Il faut gérer les deux formats (ISO et européen) dans une fonction de parsing robuste.

**`surenSaasBack/app/api/bot_construction_pointages.py:151-178`**
Fonction `handle_validate_pointage` — ligne 159 utilise déjà `statut`. C'est OK.

**`surenSaasBack/app/api/bot_construction_pointages.py:29-41`**
Fonction `_get_pointage_for_date` — crée un pointage avec `{\"chantier_id\": chantier_id, ...}`. Pas de colonne `status`. OK.

**`surenSaasBack/app/services/telegram/construction_menu.py`** (create if not exists)
Ajouter une fonction `parse_pointage_date(date_str: str) -> str` qui:
1. Essaie `date.fromisoformat()` d'abord
2. Si ValueError, essaie de parser "DD/MM/YYYY" avec `datetime.strptime(date_str, "%d/%m/%Y").date()`
3. Si nouveau ValueError, lève une erreur claire
4. Retourne toujours `date.isoformat()` (YYYY-MM-DD)

**`surenSaasBack/tests/test_telegram_construction_bot.py:330-361`**
Test `test_validate_pointage_uses_statut_column` — déjà correct, ne pas toucher.

**`surenSaasBack/tests/test_telegram_construction_bot.py:402-423`**
Test `test_pointage_list_human_uses_state_date` — déjà correct, ne pas toucher.

- Fonction de parsing de date: l'ajouter dans `construction_menu.py` avec le nom `parse_pointage_date`
- L'appeler dans `_format_date_display` au lieu de `date.fromisoformat()` direct
- Ne PAS ajouter de nouvelles dépendances pip
- Préfixer les logs avec `[PARSE_DATE]` pour traçabilité

## Expected Outcome
- Test `test_validate_pointage_uses_statut_column` passe
